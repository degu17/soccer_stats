# 07. 実装ロードマップ

> **原則: 50事件を作る前に、3事件で「面白い」を証明する。**  
> コンテンツ量は後から足せるが、コアループの面白さは後から足せない。

---

## 0. 現在地

- 既存アプリは Preact + TypeScript + Vite。1事件＝4つの独立ミニゲーム。
- 紙／インクの世界観、キャリアグラフ、正体判明の物語、効果音は強い資産。
- 途中セーブ、日替わり、コレクション、PWAは未実装。
- 今回の設計パッケージで、新しいコアループ・サンプル事件・データ型・ワイヤーフレーム・制作工程を定義した。

**このロードマップは、設計承認後の実装計画。** まだアプリのコードは変更しない。

## 2. フェーズ1: 垂直スライス（3週間）

### 目的

- 新しいコアループが**非ファンに通じる**か。
- 6人の容疑者一覧が**スマホで読める**か。
- 2枚の証拠で決まる**気持ちよさ**があるか。
- 途中セーブが**実際に使える**か。

### 作るもの

#### 事件

1. **TUTORIAL「はじめての事件」** — 4人・4手がかり・3分。
2. **FILE 001「途切れない線」** — 6人・8手がかり・6分。サンプル事件。
3. **FILE 002「左足の魔法」** — 6人・8手がかり・7分。中村俊輔が答え。海外3か国・MVP2回・最終季J2の組み合わせ。左足はタイトルとリビールの物語。

#### 画面

- タイトル（今日の事件、続きから、事件ファイル）
- 事件カード（匿名プロフィール、無料の手がかり、曲線）
- 捜査画面（容疑者一覧、手がかりタブ、状態スタンプ）
- 手がかりデッキ（8枚、購入、結果）
- 告発・証拠（容疑者1人＋証拠2枚、プレビュー）
- 正体判明（写真、名前、3ビート、数字の読み方）
- 結果（レシート、ランク、再挑戦、次の事件）
- 一時停止／設定（音、文字サイズ、アシスト）
- 事件ファイル（3件の一覧）

#### システム

- `CaseFile` / `SuspectProfile` / `Clue` の型。
- `matchesEffect` / `initialCandidates` / `evaluateEvidence` / `scoreCase`。
- 事件データの検証スクリプト。
- `CaseProgress` の保存・復元。
- ルーティング: `case/:id`、`collection`、`settings`。
- 既存の `seasons.json` を容疑者プロフィールに変換するアダプタ。
- 新規3人（小野・稲本・憲剛）のプロフィールと写真プレースホルダー。

### 週ごとの作業

#### Week 1: データとエンジン

- `src/data/caseTypes.ts` を作る（設計の `04-data-schema.ts` を移植）。
- `src/lib/caseEngine.ts` に `matchesEffect` / `initialCandidates` / `evaluateEvidence`。
- `src/lib/scoring.ts` に `scoreCase` / `rankOf`。
- `src/data/cases/tutorial.json`、`case-001.json`、`case-002.json`。
- `scripts/validate-cases.mjs`。CIで実行。
- 単体テスト: 手がかりの該当、証拠ペア、採点例。

#### Week 2: 画面

- `Case.tsx` を新しいフェーズに書き換え:
  `intro -> investigating -> evidence -> reveal -> result`
- `MysteryCard`、`SuspectList`、`SuspectSheet`、`ClueDeck`、`EvidencePicker`、`ScoreReceipt`。
- `styles.css` の既存変数を使い、新しい紙のレイヤーを追加。
- 一時停止、設定、用語ノート。
- 途中セーブ（`CaseProgress`）と復元。

#### Week 3: チュートリアル、テスト、調整

- チュートリアルの誘導（最初の手がかりを自動選択、消去アニメ、説明）。
- 375×667 / 390×844 / 430×932 のスクリーンショット。
- Playwrightで通しプレイ（購入→消去→告発→リビール→結果→再挑戦）。
- 非ファン5人＋ファン3人のプレイテスト。
- 結果を見て、手がかりのコストと文言を調整。
- **ゲート判定:** 非ファン4/5がFILE 001を解ける。S率30〜45%。中央値5〜7分。

### このフェーズでやらないこと

- 50事件の量産。
- 日替わり、実績、コレクションの豪華な演出。
- BGMの作曲（既存SFX＋仮の1曲でよい）。
- 描画モードの移植。
- オンラインランキング。
- 商用化の最終判断。

## 3. フェーズ2: Vol.1制作（6週間）

### 目的

- 10事件＋チュートリアルで、**1.5〜2時間の第1巻**を作る。日替わり・再挑戦・コレクション込みで3〜4時間。
- 制作パイプラインを回し、1事件あたりの工数を測る。

### 内容

- Vol.1「日本代表の系譜」10事件。
- 答え候補: 遠藤、俊輔、憲剛、小野、稲本、中田、大久保、中澤、川口、三浦など。
- 新要素: 代表キャップ、最終季、海外経験、J1優勝、MVP、キャリア曲線。
- コレクション: 解決した選手のカード、物語、数字の読み方。
- 日替わり: 10事件から4人・4手がかりのミニ事件を90日分。
- 実績: 初S、2枚S、全S、用語コンプ、日替わり7日。
- シェアカード: スポイラーなし画像。
- 用語ノート: 15〜20語。
- BGM: 3曲（捜査、リビール、結果）。既存SFXを調整。

### 制作の順序

1. 事件の答えと6人を決める（10件）。
2. プロフィールをデータ化（新規選手は写真も）。
3. 手がかり8枚を設計し、自動検証。
4. 物語と数字の読み方を書く。
5. 事実確認（2人）。
6. プレイテスト（各事件2人以上）。
7. 難易度調整。
8. コレクション、日替わり、実績に接続。

### ゲート

- 全10事件の自動検証が通る。
- 写真pending 0。
- 非ファン5人のうち4人がVol.1を3事件以上クリア。
- ファン5人のうち3人が「Sを狙って再挑戦したい」と答える。
- 1事件の制作工数が2〜3日以内に収まる（50事件への見通し）。

### 価格とボリュームの注意

10事件 × 6分 = 約60分。日替わり・再挑戦・コレクションを入れても、Vol.1単体は2〜3時間。**10事件で¥1,000は内容量が不足しやすい。** 推奨は次のいずれか。

- Vol.1は10事件で¥500〜700の「第1巻」にし、Vol.1〜3（30事件）で¥1,000〜1,200。
- Vol.1を20事件に増やして¥1,000。
- 50事件フルパッケージを¥1,000〜1,500にし、品質・ボリューム次第で¥1,500〜2,000も検討する。

設計は50事件フルパッケージの¥1,000〜1,500を本命にし、Vol.1は「第1巻」として位置づける。価格はフェーズ2のプレイテスト後に確定する。

## 4. フェーズ3: PWA / ポリッシュ（3週間）

### PWA

- `manifest.webmanifest`（名前、アイコン、テーマ色、表示モード standalone）。
- Service Worker:
  - App shell: cache-first。
  - 事件JSON・写真: stale-while-revalidate。
  - フォント: cache-first、subset。
  - オフライン: Vol.1の全事件と写真をプリキャッシュ。容量が大きければ、巻単位でオプションDL。
- インストール導線: タイトル画面の下に小さく「ホーム画面に追加」。
- 更新通知: 新しい巻が来たら「更新があります」。
- オフライン時の日替わり: 端末内スケジュールで90日分。

### 技術的な注意: 単一ファイルビルド

現在の `vite-plugin-singlefile` は、`dist/index.html` を直接開ける便利さがある一方、PWAのプリキャッシュ・画像の遅延読み込み・50事件の分割には不利。

**推奨:** Vol.1では通常のViteビルド（hashed assets）に切り替える。  
**代替:** 単一ファイル版は「体験版」として残し、PWA版は別ビルドにする。  
どちらでも、`dist/index.html` を直接開く互換性をどこまで残すかを決める。

### アクセシビリティ

- 文字サイズ100/125/150%。
- 色覚モード（×/○/？の形とコントラスト）。
- 低モーション（ページめくり、スタンプ、消去アニメを即時）。
- スクリーンリーダー（容疑者カードの全数値、曲線のテキスト代替、`aria-live`）。
- キーボード操作（手がかり購入→告発→結果）。
- 200%ズームで破綻しない。

### パフォーマンス

- LCP < 2.5s（4G）。
- JS < 200KB gzip（Preactの利点を活かす）。
- 写真はWebP/AVIF、事件ごとに遅延読み込み。次の事件を先読み。
- フォントは必要なウェイトだけsubset。`Dela Gothic One` は見出しのみ。
- 低スペック端末で網点フィルタを使わない（事前加工画像）。

### 音楽・効果音

- BGM 3曲: 捜査（静かなピアノ＋ベース）、リビール（弦＋金物）、結果（短いジングル）。
- 既存のWebAudio SFXを維持。購入、スタンプ、誤答、ページめくり。
- 音量設定はBGMとSFXを別々に。
- 初回はミュート。ユーザーがONにしたらフェードイン。

### シェア

- 1080×1350の画像カード。Canvasで生成。
- スポイラーなし。事件番号、ランク、使用手がかり数、URL。
- Web Share API、失敗時は画像をダウンロード＋テキストコピー。

### 計測

- プライバシーに配慮したイベント:
  `tutorial_start`, `case_start`, `clue_buy`, `suspect_eliminate`, `evidence_select`, `accuse`, `case_clear`, `retry`, `daily_play`.
- 個人情報は送らない。オプトイン。
- 離脱画面、平均手がかり数、S率をダッシュボードで見る。

## 7. セーブのマイグレーション

現在の `Save` は v1。新しい `SaveDataV2` へ移行する。

- `sound`, `terms`, `tutorialSeen` は引き継ぐ。
- `results` は新しい `CaseResult` に変換できない（採点体系が違う）。**一度リセット**し、初回起動時に「新しい事件ファイルに生まれ変わりました。用語ノートは引き継がれます」と通知する。
- 途中の事件進行はv1に存在しないので、移行不要。
- `version` フィールドで判別。未知のバージョンは安全に初期化。
- セーブは `localStorage` から `IndexedDB` へ移行する（写真・事件JSONのキャッシュと一緒に管理するため）。最初は `localStorage` でもよいが、50事件＋画像を考えるとIndexedDBが安全。

## 8. テスト計画

- 手がかり購入 → 容疑者消去 → 証拠選択 → 告発 → 結果。
- 誤告発 → 捜査に戻る → 再告発。
- リロード → 途中復元。
- 予算不足 → 購入不可。
- 証拠2枚未満 → 告発不可。
- 写真pending → シルエット。

### E2E（Playwright）

- 375×667、390×844、430×932。
- チュートリアルを通しで。
- FILE 001を2ptルートでS。
- FILE 001を4ptルートでA。
- 誤告発1回でA。
- 日替わり1件。
- コレクション解放。
- 設定変更の永続化。

### アクセシビリティ

- axeで重大0。
- キーボードだけで通し。
- スクリーンリーダー（VoiceOver / NVDA）で容疑者カードと証拠選択。
- 200%ズーム。
- 色覚シミュレーション。

### パフォーマンス

- Lighthouseモバイル: Performance 90以上、Accessibility 95以上、PWA installable。

- 画像の合計がVol.1で10MB以下（WebP）。

## 9. リスクと対策

| リスク | 対策 |
|---|---|
| 3事件で面白くない | フェーズ1のゲートを厳守。50事件に進まない |
| 非ファンが用語で離脱 | チュートリアルと1行説明。プレイテストで検証 |

| 写真が揃わない | Vol.1の3人を先に確保。pendingはリリース不可 |

| セーブ移行で不具合 | v1リセット＋用語引き継ぎ。テストを書く |
| スコープが膨らむ | フェーズ1では日替わり・実績・BGMを作らない |
